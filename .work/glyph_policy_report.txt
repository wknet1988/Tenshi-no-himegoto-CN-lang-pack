天使のひめごと 汉化 —— 字形选用策略重建报告
日期：2026-10-16

====================================================================
一、起因：用户反馈不合适的替换
====================================================================
用户实例：中文「这」在游戏里显示为「迄」。

根因：旧的 .work/glyph_map.json 采用「字形部件相似」兜底 —— 找不到可编码字形时，
      挑一个长得像的日本汉字顶替。这 → 与「这」同为辶旁、外形相近的「迄」（意思是“到…
      为止”），语义完全错位。

同类问题不止一例，例如：
  疲惫 → 疲倦        （被近义替换，词都变了）
  实   → 実          （取了日文简体，而非正字）
  变   → 変          （同上）
  图   → 図 / 圆 → 円 （取日文简体）
  碰   → 触          → 造成「触碰」渲染成「触触」（与邻字同形）

====================================================================
二、新策略（按用户指定）
====================================================================
对每一个 Shift-JIS(cp932) 无法直接编码的汉字，按序取其第一个可编码者：
  1) 繁体中文字形    （OpenCC s2t / zhconv）
  2) 日文新、旧字体  （OpenCC t2jp）
  3) 只有 1)2) 都不可用时，才用「意思相近的字」替换
渲染安全性：优先选能被严格 shift_jis（JIS X 0208 标准区）编码的字形，
           cp932 厂商扩展区作为次选，以降低缺字形风险。
明确废弃：原先的「形近/部件相似」兜底。

五、第三轮：拟声词 / 语气助词 / 人称代词
====================================================================
用户反馈「拟声词没处理好」。深挖发现是同一根因的更大一类问题：
日语要用「多个假名」表达的东西，被旧表压成了单个假名或错字，例如
    她 → あ        （人称代词！出现 101 次，最伤的一处）
    吧 → ば        对吧？→ 對ば？
    啦 → ら        再见啦 → 再見ら
    嗯 → ン        误用片假名；日文原文是平假名「ん、」「んーーーんっ」

【治本】给 tools/to_jp.py 增加「一字 → 多个假名」支持：
   新增 usable() —— 值可以是多字符，只要其中每个字符都是合法 Shift-JIS 双字节
   （放宽了原「值必须是单字符」的限制；字节 walk 依然对齐，不受影响）
